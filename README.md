# Планировщик задач

Проект представляет собой веб-приложение для управления задачами с поддержкой повторяющихся событий. Основной функционал:
- Создание, редактирование, удаление задач;
- Отметка выполнения задач с автоматическим обновлением даты для повторяющихся событий;
- Поиск задач по дате, заголовку или комментарию;
- Расчёт следующей даты для задач с правилами повтора (ежедневно, еженедельно, ежемесячно, ежегодно).

## Выполненные задания со звёздочкой
Выполнены все задания повышенной сложности, кроме механизма аутентификации (возможно будет выполнено позднее, но это не точно).

#Важное уточнение - для правила повторения "ежемесячно" функция NextDate умеет работать не только с последним/предпоследним днем месяца, а вообще с любым отрицательным числом (в пределах количества дней в месяце). В браузере, к сожалению, нельзя задать в поле "Дни месяца (через запятую)" - судя по всему из-за фронтовой валидации (руки пока не дошли разобраться и поправить), но бэк будет отрабатывать корректно. Из-за несколько расширенного функционала NextDate - пришлось подкорректировать один из тестов, а именно nextdate_3_test.go (тестовые данные {"20240222", "m -2,-3", ""}).
В моем случае функция NextDate с -3 отработает корректо и результатом будет "20240227". 2024 год - високосный, 29 дней в феврале - соответственно -3 дает 27 февраля.

## Инструкция по запуску локально

Для запуска необходим установленный Go.
### Шаги:
1. Клонируйте репозиторий:
   git clone https://github.com/DDmitrievskiy/go_final_project
   cd go_final_project
2. Установите зависимости:
   go mod download   
3. Опционально можно создать файл .env со значениями:
   TODO_PORT=7540         # Порт сервера
   TODO_DBFILE=./scheduler.db  # Путь к файлу БД
4. Выполнить go build, запустить приложение
   go build -o app ./
   ./app
5. Открыть в браузере:
   http://localhost:7540


### Запуск тестов

В файле tests/settings.go можно настроить параметры базы данных для тестов. 
Для запуска тестов выполните команду go test ./tests

### Сборка и запуск через Docker

Соберите образ с помощью docker build -t scheduler-app .
Команда для запуска контейнера
  docker run -d \
  -p 7540:7540 \
  -v /путь/к/вашей/папке/data:/db \      # монтирует директорию хоста в контейнер для хранения SQLite-базы.
  -e TODO_DBFILE=/db/scheduler.db \      # Путь к базе внутри контейнера
  scheduler-app
